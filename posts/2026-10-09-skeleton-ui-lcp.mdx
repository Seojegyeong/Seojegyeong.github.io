whereYouAd 통합 대시보드는 KPI 카드·트래픽 차트·예산 게이지 등 여러 섹션으로 구성되고, 각 섹션이 독립적으로 API를 요청합니다. 처음 진입하면 6~8개 API가 동시에 실행되는데, 응답이 오기 전까지 각 섹션이 빈 공간으로 표시됐습니다. 실제 사용자 테스트에서 "페이지가 깨진 것 같다"는 피드백이 있었습니다.

## 빈 화면은 레이아웃도 무너뜨린다

콘텐츠 영역에 높이가 잡히지 않으면 API 응답이 도착할 때 화면이 한꺼번에 밀립니다. 이것이 CLS(Cumulative Layout Shift)입니다. 섹션이 독립적으로 응답을 받아오면 차례로 나타나면서 레이아웃이 여러 번 흔들립니다.

"Skeleton UI를 적용해 LCP가 개선됐다"고 주장하려면 수치가 필요했습니다. 느낌만으로는 설득력이 없습니다.

## 섹션별 Skeleton 적용

각 섹션에 실제 레이아웃과 동일한 크기의 Skeleton을 fallback으로 설정했습니다.

```tsx
// OverviewDashboard.tsx
<Suspense fallback={<OverviewKpiCardSkeleton />}>
  <OverviewKpiCards />
</Suspense>

<Suspense fallback={<OverviewBudgetGaugeSkeleton />}>
  <BudgetGauge />
</Suspense>

<Suspense fallback={<TrafficChartSkeleton />}>
  <TrafficChart />
</Suspense>
```

Skeleton은 실제 레이아웃과 동일한 크기의 회색 플레이스홀더입니다. API 응답이 오면 Skeleton이 실제 데이터로 교체됩니다. 레이아웃이 미리 잡혀 있으므로 데이터가 채워질 때 레이아웃 이동이 없습니다.

## LCP 비교 측정 방법

임시 브랜치 `perf/no-skeleton`을 만들어 Skeleton을 제거하고 AuthGuard를 우회한 상태로 빌드했습니다. 동일 조건에서 각 3회 측정해 평균을 비교했습니다.

- **도구**: Chrome DevTools Lighthouse (Navigation, Desktop)
- **대상**: `/dashboard` OverviewDashboard
- **BEFORE**: `perf/no-skeleton` 브랜치
- **AFTER**: `main` 브랜치 (Skeleton 적용)

### 측정 결과

| 지표 | BEFORE | AFTER | 변화 |
|------|--------|-------|------|
| **LCP** | **1,180ms** | **1,048ms** | **−132ms (−11%)** |
| CLS | 0.000172 | 0.000304 | +0.000132 |
| TBT | 54ms | 54ms | 변화 없음 |

LCP가 개선되는 이유는 브라우저가 "의미 있는 콘텐츠가 그려진 시점"을 인식하는 방식에 있습니다. 빈 화면 상태에서는 실제 데이터가 도착할 때까지 LCP 대상이 없어 측정이 늦어집니다. Skeleton이 먼저 렌더되면 브라우저는 그 시점을 콘텐츠 렌더 시점으로 인식합니다.

CLS가 소폭 증가한 이유는 Skeleton → 실제 콘텐츠 전환 시 미세한 레이아웃 이동이 발생하기 때문입니다. 둘 다 0.1 기준 대비 사실상 0 수준이라 사용자 체감 영향은 없습니다.

## Lighthouse CI에서 LCP를 자동 감지하지 못하는 이유

`@lhci/cli`로 PR마다 Lighthouse를 자동화했지만, CI 환경에서 `AuthGuard` 때문에 `/dashboard`에 접근할 수 없습니다. accessToken이 Zustand 메모리에만 있어 CI에서 주입할 수도 없습니다. `/login` 페이지만 측정 가능한데, `Login` 컴포넌트도 lazy load 대상이라 GitHub Actions 러너(느린 CPU)에서 LCP가 항상 ~15,000ms로 측정됩니다.

이 때문에 LCP는 `warn`으로 유지하고, 환경 영향을 적게 받는 CLS와 TBT만 `error` 임계값으로 자동 차단합니다. `/dashboard` LCP는 로컬에서 직접 측정하는 방식으로 관리합니다.

## 정리

Skeleton UI는 두 가지를 동시에 해결합니다. 사용자에게 로딩 중임을 명확히 알리고, 레이아웃을 미리 잡아 데이터 도착 시 CLS를 방지합니다. LCP 개선 효과는 실측으로 확인했습니다. "체감이 좋아졌다"가 아닌 "LCP 11% 감소"로 말할 수 있습니다.
