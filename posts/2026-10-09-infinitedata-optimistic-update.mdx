Roome Feed·Shop의 제품 목록에서 좋아요·스크랩 버튼을 클릭하면 서버 응답이 올 때까지 버튼 상태가 변하지 않았습니다. ~300ms 대기는 클릭이 됐는지 안 됐는지 모호하게 만들었습니다. 낙관적 업데이트를 적용하려 했는데, InfiniteQuery 구조 때문에 단순히 `setQueryData`를 쓰는 것으로는 해결이 안 됐습니다.

## 두 가지 구조적 어려움

**첫 번째 — InfiniteData 중첩 구조**

InfiniteQuery가 관리하는 캐시는 중첩된 구조입니다.

```text
InfiniteData<Page> = {
  pages: [
    { content: [item1, item2, ...], hasNext: boolean },  // 1페이지
    { content: [item3, item4, ...], hasNext: boolean },  // 2페이지
  ],
  pageParams: [...]
}
```

특정 아이템의 좋아요 상태를 변경하려면 `pages[n].content[m]`까지 들어가야 합니다. 단순히 `setQueryData`에 새 값을 넘기면 전체 페이지 구조가 사라집니다.

**두 번째 — 필터 조합마다 독립 캐시**

같은 제품이 필터에 따라 서로 다른 캐시 키에 있습니다.

```text
["feed", "products", { category: "all" }]
["feed", "products", { category: "sofa" }]
["feed", "products", { category: "sofa", sort: "popular" }]
```

"전체" 탭에서 좋아요를 누르고 "소파" 탭으로 이동하면 좋아요 상태가 반영되지 않은 구버전이 표시됩니다.

## getQueriesData 접두사 매칭으로 일괄 업데이트

`getQueriesData`는 접두사로 매칭되는 모든 캐시를 배열로 반환합니다. `["feed", "products"]`를 키로 주면 필터 조합에 무관하게 관련 InfiniteQuery 캐시를 모두 가져옵니다.

```ts
const onMutate = async ({ productId, isLiked }: { productId: number; isLiked: boolean }) => {
  await queryClient.cancelQueries({ queryKey: ["feed", "products"] });

  // 접두사 매칭으로 모든 관련 캐시 수집
  const previousCaches = queryClient.getQueriesData<InfiniteData<IProductPage>>({
    queryKey: ["feed", "products"],
  });

  // 모든 캐시를 순회하며 대상 아이템만 업데이트
  previousCaches.forEach(([queryKey, data]) => {
    if (!data) return;
    queryClient.setQueryData<InfiniteData<IProductPage>>(queryKey, {
      ...data,
      pages: data.pages.map((page) => ({
        ...page,
        content: page.content.map((item) =>
          item.productId === productId
            ? { ...item, isLiked, likeCount: isLiked ? item.likeCount + 1 : item.likeCount - 1 }
            : item
        ),
      })),
    });
  });

  // 상세 캐시도 동시에 동기화
  const detailCache = queryClient.getQueryData<IProductDetail>(["feed", "product", productId]);
  if (detailCache) {
    queryClient.setQueryData(["feed", "product", productId], { ...detailCache, isLiked });
  }

  return { previousCaches, previousDetail: detailCache };
};

const onError = (err: unknown, _: unknown, context: ReturnType<typeof onMutate> | undefined) => {
  context?.previousCaches.forEach(([queryKey, data]) => {
    queryClient.setQueryData(queryKey, data);
  });
  if (context?.previousDetail) {
    queryClient.setQueryData(["feed", "product", variables.productId], context.previousDetail);
  }
};

const onSettled = () => {
  queryClient.invalidateQueries({ queryKey: ["feed", "products"] });
};
```

`onMutate`에서 업데이트 전 모든 캐시 값을 저장해두고, `onError`에서 원래 값으로 되돌립니다. `onSettled`에서 서버와 최종 동기화합니다.

## getQueryData vs getQueriesData

`getQueryData`는 정확히 일치하는 단일 키의 캐시를 반환합니다. `getQueriesData`는 접두사나 필터 기준으로 매칭되는 모든 캐시를 `[queryKey, data]` 배열로 반환합니다. 필터 조합마다 다른 키를 가진 캐시를 한 번에 처리할 때 유용합니다.

## 트레이드오프

모든 관련 캐시를 순회하므로 캐시 수가 많아지면 업데이트 비용이 커집니다. rollback을 위해 이전 캐시 전체를 `context`에 저장하므로 메모리 사용량도 캐시 수에 비례합니다.

동일 패턴을 제품 좋아요·스크랩·레퍼런스 좋아요·스크랩 4종에 적용했는데, 추상화 없이 반복했습니다. 구조가 변경될 때 4곳을 수정해야 하는 기술 부채로 남아 있습니다.

## 정리

`getQueriesData`로 접두사 매칭해 분산된 캐시를 일괄 업데이트하는 것이 핵심이었습니다. 버튼 클릭 즉시 UI가 반응하고, 서버 실패 시 전체 rollback, `onSettled`에서 최종 동기화하는 3단계 구조로 InfiniteData 환경에서 낙관적 업데이트를 완성했습니다.
