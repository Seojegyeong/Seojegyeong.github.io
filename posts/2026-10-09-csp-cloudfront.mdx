whereYouAd는 accessToken을 Zustand 메모리에만 저장해 XSS 탈취 피해를 최소화했습니다. 그런데 메모리 저장은 2차 방어입니다. 악성 스크립트가 실행된 후 localStorage처럼 직접 접근하지 못하게 막는 것입니다. **1차 방어는 악성 스크립트가 실행되는 것 자체를 막는 것**입니다. Content Security Policy(CSP)가 이 역할을 합니다.

## CSP 헤더를 추가하는 위치

CSP는 HTTP 응답 헤더로 전달됩니다. whereYouAd는 S3 + CloudFront 구조의 SPA입니다. 서버가 HTML을 서빙하지 않으므로 백엔드 코드에서 헤더를 추가할 수 없습니다.

HTML `<meta>` 태그로도 CSP를 선언할 수 있지만 `frame-ancestors` 등 일부 디렉티브를 지원하지 않습니다.

CloudFront Response Headers Policy를 콘솔에서 설정하면 되지만 Business 플랜이 필요했습니다. 대안으로 **CloudFront Functions**를 사용했습니다. 엣지 서버에서 모든 응답에 헤더를 추가하는 경량 JavaScript 함수입니다. 월 200만 건까지 무료이며 별도 플랜이 필요하지 않습니다.

## Report-Only → Enforcing 2단계 전환

enforcing 모드를 바로 적용하면 허용하지 않은 리소스 로드가 차단됩니다. 초기에는 어떤 도메인·패턴을 명시해야 하는지 파악이 안 됩니다. `Content-Security-Policy-Report-Only` 헤더를 먼저 적용해 위반 항목을 콘솔에 경고만 표시했습니다. 전체 기능 테스트 후 위반 없음을 확인하고 enforcing으로 전환했습니다.

## 최종 CSP 정책과 선택 이유

```text
default-src 'self';
script-src 'self' 'unsafe-eval';
connect-src 'self' https://api.whereyouad.com https://*.ingest.sentry.io;
img-src 'self' data: blob: https://*.amazonaws.com;
style-src 'self' 'unsafe-inline';
font-src 'self' https://fonts.gstatic.com https://fonts.googleapis.com;
frame-ancestors 'none';
base-uri 'self';
object-src 'none';
```

| 디렉티브 | 이유 |
|----------|------|
| `script-src 'unsafe-eval'` | ApexCharts 5.x가 내부적으로 `new Function()` 사용 |
| `style-src 'unsafe-inline'` | Framer Motion 애니메이션 값·Tailwind v4 런타임 인라인 주입 |
| `img-src data: blob:` | 차트 PNG 다운로드(`data:`), PDF 생성(`blob:`) |
| `img-src *.amazonaws.com` | 워크스페이스 프로필 이미지 S3 직접 URL |
| `frame-ancestors 'none'` | 클릭재킹 방지 |
| `connect-src *.ingest.sentry.io` | Sentry SDK 이벤트 전송 허용 |

Report-Only로 테스트하면서 발견한 중요한 사항이 하나 있었습니다. `VITE_API_BASE_URL`이 `https://api.whereyouad.com`(별도 서브도메인)임을 확인했습니다. `connect-src 'self'`만 있으면 enforcing 모드에서 모든 API 호출이 차단됩니다. `https://api.whereyouad.com`을 명시적으로 추가해야 했습니다.

## CI/CD 자동화

CSP 정책을 코드로 관리하고 배포 시 CloudFront Function에 자동 반영했습니다.

```yaml
# .github/workflows/main.yaml
- name: Update CloudFront CSP Function
  run: |
    ETAG=$(aws cloudfront describe-function \
      --name add-csp-report-only --query 'ETag' --output text)
    aws cloudfront update-function \
      --name add-csp-report-only --if-match "$ETAG" \
      --function-config Comment="CSP security headers",Runtime="cloudfront-js-2.0" \
      --function-code fileb://scripts/cloudfront-functions/csp-headers.js
    NEW_ETAG=$(aws cloudfront describe-function \
      --name add-csp-report-only --query 'ETag' --output text)
    aws cloudfront publish-function \
      --name add-csp-report-only --if-match "$NEW_ETAG"
```

`scripts/cloudfront-functions/csp-headers.js`가 CSP 정책의 SSOT입니다. 이 파일만 수정하면 배포 시 자동으로 반영되어 콘솔 수동 작업이 필요 없습니다.

## 트레이드오프

`'unsafe-eval'`을 허용했습니다. ApexCharts가 내부적으로 `new Function()`을 사용하기 때문입니다. 이는 CSP의 핵심 방어 기능 중 하나를 포기하는 것입니다. ApexCharts를 교체하거나 nonce 기반으로 전환하면 제거할 수 있습니다.

`'unsafe-inline'`(styles)도 Tailwind v4와 Framer Motion이 런타임 인라인 스타일을 사용하기 때문에 허용했습니다.

## 정리

XSS 방어는 두 레이어가 함께 작동해야 합니다. CSP는 허용되지 않은 스크립트 실행 자체를 막고, 메모리 저장은 스크립트가 실행되더라도 직접 접근할 수 없게 합니다. S3+CloudFront SPA 구조에서 CSP를 추가하는 가장 간단한 방법은 CloudFront Functions였고, CI/CD에 통합해 정책 변경이 코드 리뷰와 배포 파이프라인을 통해 관리됩니다.
